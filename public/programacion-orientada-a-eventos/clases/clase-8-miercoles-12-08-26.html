GUÍA DE PRÁCTICA ⏱️ 90 MINUTOS 👥 INDIVIDUAL / PAREJAS

Spider-Verse: Registro de Héroes

Aplicación de POE con TypeScript — Eventos, validaciones y funcionalidades interactivas

🧩

Código Base

PARTES INCLUIDAS

📌 El código base ya incluye:

  • interface Heroe — Definición del tipo de datos de los héroes.
  • Objeto DOM — Selección de elementos del HTML (botones, inputs, select, contenedor).
  • Arreglo heroes — Almacenamiento de los héroes registrados.
  • Funciones agregarHeroe() y eliminarHeroe() — Operaciones CRUD básicas.
  • Función renderizarHeroes() — Genera las tarjetas HTML de cada héroe.
  • Delegación de eventos con closest() — Manejo de eventos en elementos dinámicos.

📌 Regla del ejercicio: Cada punto se prueba en el navegador antes de pasar al siguiente. Si algo no compila, no avanzan — deben resolverlo primero (así se acostumbran a leer errores de TypeScript).

📋 Bloques: 1️⃣ Calentamiento 2️⃣ Validaciones 3️⃣ Favoritos 4️⃣ Filtro y Orden 5️⃣ Reto Final
⏱️ Total: 90 min
BLOQUE 1

Calentamiento

15 min

Objetivo: Perder el miedo a tocar el código base. Modificar sin romper nada.

PUNTO 1

🕐 Fecha y hora

Cambien el mensaje de bienvenida en consola (init()) para que también muestre la fecha y hora actual usando new Date().

PUNTO 2

🌌 Nuevo universo

Agreguen una nueva opción al <select> del HTML con un universo inventado por ustedes (ej. "Tierra-XXXX — su propio personaje"), y verifiquen que aparece correctamente al reclutarlo.

PUNTO 3

📊 Log de cambios

En actualizarEstado(), agreguen un console.log que muestre el arreglo heroes completo cada vez que cambia. Ábranlo en la consola del navegador y observen cómo crece y decrece.

BLOQUE 2

Validaciones

20 min

Refuerza: if, tipado de strings, manipulación de estilos desde eventos.

PUNTO 4

🚫 Nombres duplicados

Antes de agregar un héroe en agregarHeroe(), verifiquen si ya existe uno con el mismo nombre (usen .some() o .find() sobre el arreglo heroes). Si existe, muestren un mensaje de error y no lo agreguen.

PUNTO 5

✏️ Límite de caracteres

El nombre no debe superar los 20 caracteres. Si el usuario escribe más, corten el string o muestren un error (a elección de ustedes, pero deben justificar cuál eligieron y por qué).

PUNTO 6

👥 Límite de héroes

El equipo no puede tener más de 6 héroes a la vez. Si se intenta agregar un séptimo, el botón btnAgregar debe deshabilitarse (disabled = true) y mostrar un mensaje explicando por qué. Al eliminar uno, el botón debe volver a habilitarse.

BLOQUE 3

Nueva Funcionalidad: Favoritos

25 min

Refuerza: Modificar la interfaz Heroe, classList.toggle, delegación de eventos.

PUNTO 7

🔖 Agregar propiedad a la interfaz

Agreguen una propiedad nueva a la interfaz Heroe:

interface Heroe {
  id: number;
  nombre: string;
  universo: string;
  esFavorito: boolean; // <-- nueva propiedad
}
PUNTO 8

🔄 Inicializar favoritos

Ajusten agregarHeroe() para que todo héroe nuevo empiece con esFavorito: false.

PUNTO 9

🎨 Botón de favorito en plantilla

En la plantilla HTML de cada tarjeta (dentro de renderizarHeroes), agreguen un botón nuevo:

<button class="btn-favorito" data-id="${heroe.id}">
  ${heroe.esFavorito ? 'Quitar de favoritos' : 'Marcar como favorito'}
</button>
PUNTO 10

🔄 Función toggleFavorito

Creen una función toggleFavorito(id: number): void que busque el héroe por id e invierta su propiedad esFavorito (heroe.esFavorito = !heroe.esFavorito), y luego vuelva a renderizar.

PUNTO 11

🔗 Conectar el botón (Delegación de eventos)

Conecten el nuevo botón usando el mismo patrón de delegación de eventos que ya existe para "Expulsar" — no creen un addEventListener nuevo suelto, agréguenlo dentro de setupEliminarHeroes (o creen setupBotonesHeroe si prefieren separar responsabilidades).

💡 Reflexión: ¿Por qué el botón de favorito no necesita un addEventListener nuevo? Piensen en la delegación de eventos y el método closest().

🎨 Bonus visual: Agreguen una clase CSS .favorito que le dé un borde dorado a la tarjeta, y actívenla/desactívenla con classList.toggle('favorito', heroe.esFavorito).

BLOQUE 4

Filtro y Orden

20 min

Refuerza: .filter(), .sort(), eventos en un <select> con "change".

PUNTO 12

🔍 Selector de filtro

Agreguen un nuevo <select> en el HTML con las opciones: Todos, Solo favoritos, Tierra-616, Tierra-1610, Tierra-65.

PUNTO 13

🎯 Evento "change" y filtrado

Escuchen el evento "change" de ese select (no "click" — investiguen la diferencia) y, según la opción elegida, filtren qué tarjetas se muestran.

💡 Sugerencia: No toquen el arreglo heroes original, generen un arreglo filtrado dentro de renderizarHeroes antes de hacer el .map().

PUNTO 14

📋 Orden alfabético

Agreguen un botón "Ordenar alfabéticamente" que reordene heroes usando .sort() comparando nombre con localeCompare().

BLOQUE 5

Reto Final / Extensión Libre

10 min

Elijan UNO de estos, el que más les interese:

OPCIÓN A

✏️ Edición en línea

Al hacer clic en el nombre de un héroe, que se convierta en un <input> editable, y al presionar Enter o perder el foco ("blur"), se guarde el cambio.

OPCIÓN B

💾 Persistencia

Investiguen localStorage.setItem() y localStorage.getItem(), y hagan que la lista de héroes sobreviva si recargan la página.

OPCIÓN C

📊 Contador por universo

Un pequeño resumen que muestre cuántos héroes hay de cada universo (ej. "Tierra-616: 2, Tierra-1610: 1").
