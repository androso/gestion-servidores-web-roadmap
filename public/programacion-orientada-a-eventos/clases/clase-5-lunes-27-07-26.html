El Sistema de Alerta de la Policía de Nueva York

En esta clase, exploraremos los fundamentos de la Programación Orientada a Eventos a través de un sistema de alertas policiales. Analizaremos los conceptos de emisores, oyentes, eventos y suscripciones, todos ellos implementados con EventEmitter en TypeScript.

📌 Emisor 📌 Evento 📌 Oyente 📌 Suscripción 📌 Interfaz
📦

Importación de Módulos: EventEmitter

// Importamos 'EventEmitter' desde el módulo nativo 'events' de Node.js.
import { EventEmitter } from 'events';

📌 ¿Qué es EventEmitter?

Es la clase base que nos permite emitir (disparar) y escuchar eventos en JavaScript/TypeScript. Es el corazón de la Programación Orientada a Eventos en Node.js.

🎯 ¿Para qué sirve?

  • .emit() → Dispara un evento.
  • .on() → Registra un oyente para un evento.
  • .once() → Registra un oyente que se ejecuta una sola vez.
  • .off() → Elimina un oyente.

💡 Analogía: EventEmitter es como una emisora de radio que transmite señales. Los oyentes son los receptores que escuchan una frecuencia específica.

📐

Interfaces en TypeScript

// Una interfaz define la "forma" o contrato que deben cumplir los datos.
interface AlertaCrimen {
  lugar: string;
  villano: string;
  nivelPeligro: 'Bajo' | 'Medio' | 'Alto';
}

📌 ¿Qué es una interfaz?

Define el contrato que deben cumplir los datos. Especifica qué propiedades debe tener un objeto y de qué tipo son.

🔹 ¿Para qué sirve?

No genera código ejecutable en JavaScript. Solo sirve en tiempo de desarrollo para asegurarnos de que no nos equivoquemos en los nombres de las propiedades ni en sus tipos.

🔹 Tipo Unión

'Bajo' | 'Medio' | 'Alto' es un tipo unión de literales. Solo permite uno de esos 3 textos exactos. ¡Adiós errores de dedo!

💡 Para POE: Las interfaces son esenciales para definir la estructura de los datos que transportan los eventos. Aseguran que los emisores y oyentes usen el mismo formato.

🚨

Clase Emisora (El Origen del Evento)

// Usamos 'extends EventEmitter' para heredar todos los métodos
class CentralPoliciaNY extends EventEmitter {
  public reportarIncidente(lugar: string, villano: string, nivelPeligro: 'Bajo' | 'Medio' | 'Alto'): void {
    // 1. Mensaje por consola
    console.log(`\n🚨 [RADIO POLICIAL]: ¡Atención! Se reporta un problema en ${lugar}.`);
    
    // 2. Empaquetar datos
    const detallesAlerta: AlertaCrimen = { lugar, villano, nivelPeligro };
    
    // 3. Emitir el evento
    this.emit('crimenEnProceso', detallesAlerta);
  }
}

📌 extends EventEmitter

Al usar extends, nuestra clase hereda todos los métodos de EventEmitter, como .emit(), .on(), .once(), etc.

📌 this.emit()

Notifica al sistema que ocurrió un evento. Significa: "¡Atención a todos los que estén escuchando 'crimenEnProceso', ejecuten sus acciones y tomen estos datos!"

💡 Concepto clave: El emisor no sabe quién escucha. Solo emite el evento y no le importa qué sucede después. Esto es desacoplamiento.

👂

Clases Escuchadoras (Los Oyentes)

// Estas clases NO necesitan heredar de EventEmitter
// Son simples clases con métodos que se ejecutarán cuando el evento sea emitido.

class SpiderMan {
  public columpiarseAlLugar(alerta: AlertaCrimen): void {
    console.log(`🕸️ [Spider-Man]: Me columpio hacia ${alerta.lugar} para detener a ${alerta.villano}.`);
  }
}

class PeriódicoDailyBugle {
  public publicarNoticia(alerta: AlertaCrimen): void {
    console.log(`📰 [Daily Bugle]: ¡ÚLTIMA HORA! Fotos de ${alerta.villano} en ${alerta.lugar}.`);
  }
}

📌 ¿Qué son los oyentes?

Son clases o funciones que reaccionan a un evento. Definen qué hacer cuando el evento ocurre.

🔹 Características

No heredan de EventEmitter. Son independientes y desacopladas del emisor. Pueden ser múltiples oyentes para un mismo evento.

🔹 Reacción personalizada

Cada oyente reacciona de forma diferente al mismo evento. Spider-Man se columpia, el Daily Bugle publica una noticia.

💡 Para POE: Los oyentes son el "efecto" que ocurre cuando el "causa" (evento) sucede. Son los handlers o controladores de eventos.

📎

Suscripción (.on) - Múltiples Oyentes

// .on(nombreDelEvento, callback) registra una función "escuchadora"

// Suscripción 1: Spider-Man escucha el evento
centralPolicia.on('crimenEnProceso', (alerta: AlertaCrimen) => {
  spidey.columpiarseAlLugar(alerta);
});

// Suscripción 2: Daily Bugle escucha el mismo evento
centralPolicia.on('crimenEnProceso', (alerta: AlertaCrimen) => {
  dailyBugle.publicarNoticia(alerta);
});

📌 ¿Qué es .on()?

Registra una función escuchadora (listener). Significa: "Cada vez que el emisor emita este evento, ejecuta esta función".

🔹 Múltiples oyentes

Puedes registrar muchos oyentes para el mismo evento. Todos se ejecutarán a la vez cuando el evento sea emitido.

🔹 Patrón Pub/Sub

Esto es el patrón Publish/Subscribe. El emisor publica un evento y los suscriptores reciben la notificación.

💡 Concepto clave: .on() es la forma de suscribirse a un evento. Es el "contrato" entre el emisor y el oyente: "Cuando pase X, haz Y".

🔄

Flujo Completo de POE

1. Emisor
→
2. Evento
→
3. Datos
→
4. Oyentes
→
5. Acción

📌 Paso a paso

  1. Emisor crea el evento (.emit()).
  2. Evento es disparado con un nombre.
  3. Datos (opcionales) son enviados.
  4. Oyentes registrados con .on() reciben el evento.
  5. Acción es ejecutada por cada oyente.

🔹 Ventajas de este flujo

  • Desacoplamiento: Emisor y oyentes no se conocen.
  • Escalabilidad: Añadir oyentes sin modificar el emisor.
  • Flexibilidad: Cada oyente reacciona a su manera.
  • Mantenibilidad: Cambios en un oyente no afectan a otros.

💡 Analogía del restaurante: El cocinero (emisor) prepara un plato (evento). El mesero (sistema) lo lleva a la mesa correcta. Cada comensal (oyente) reacciona de forma diferente: uno come, otro toma foto, otro pide más salsa.

⚡

Instanciación y Ejecución

// 1. Instanciación (crear objetos)
const centralPolicia = new CentralPoliciaNY();
const spidey = new SpiderMan();
const dailyBugle = new PeriódicoDailyBugle();

// 2. Suscripciones (.on)
centralPolicia.on('crimenEnProceso', (alerta) => spidey.columpiarseAlLugar(alerta));
centralPolicia.on('crimenEnProceso', (alerta) => dailyBugle.publicarNoticia(alerta));

// 3. Emitir eventos (pruebas)
centralPolicia.reportarIncidente('Times Square', 'Duende Verde', 'Alto');
centralPolicia.reportarIncidente('Banco Central', 'Rhino', 'Medio');

📌 Instanciación

Creamos objetos reales en memoria a partir de las clases. Cada objeto tiene su propio estado y métodos.

📌 Suscripción

Registramos qué oyentes reaccionarán a qué eventos. Es el "contrato" entre emisor y oyente.

📌 Emisión

Al llamar a reportarIncidente(), internamente se hace .emit(). Esto activa en cadena a todos los oyentes registrados.

💡 Concepto clave: Los oyentes no se ejecutan hasta que el evento ocurre. El programa no se bloquea esperando; simplemente escucha.

Resumen de Conceptos Clave

📦 EventEmitter

Clase base que permite emitir y escuchar eventos en Node.js.

📐 Interfaces

Definen el contrato de los datos. Aseguran que emisores y oyentes usen el mismo formato.

🚨 Clase Emisora

Extiende EventEmitter y contiene la lógica para emitir eventos.

👂 Clases Oyentes

Clases independientes que definen qué hacer cuando ocurre un evento.

📎 Suscripción (.on)

Registra múltiples oyentes para un mismo evento. Cada uno reacciona de forma diferente.

🔄 Flujo POE

Emisor → Evento → Datos → Oyentes → Acción. Desacoplamiento y escalabilidad.

💡 Conclusión: Este sistema de eventos es la base de la Programación Orientada a Eventos. Emisores, oyentes, eventos y suscripciones trabajan juntos para crear sistemas reactivos, desacoplados y escalables.
