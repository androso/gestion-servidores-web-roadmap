🌟 Importancia de la Programación Basada en Eventos

Debido al uso intensivo de aplicaciones altamente interactivas, procesos asíncronos y comunicación en tiempo real, la programación orientada a eventos se erige como un factor clave en el desarrollo de aplicaciones. Esta proporciona una interfaz para crear software que responde a entradas externas.

Teoría

RECORDATORIO Programación Secuencial

Hasta ahora, los programas se ejecutaban así:

Inicio ↓ Leer datos ↓ Procesar ↓ Mostrar resultado ↓ Fin
console.log("Inicio");
console.log("Ingrese su nombre");
let nombre = "Panchito";
console.log("Hola " + nombre);
console.log("Fin");

// Salida:
// Inicio
// Ingrese su nombre
// Hola Panchito
// Fin

Todo ocurre de arriba hacia abajo. El programa controla el flujo.

¿QUÉ CAMBIA? El programa ya no decide cuándo ejecutar
Programa iniciado ↓ Esperar ↓ ¿Ocurrió un evento? ↓ Sí Ejecutar una función

El programa espera. No sabe cuándo ocurrirá el evento.

DEFINICIÓN

La Programación Orientada a Eventos es un paradigma donde el flujo del programa depende de eventos generados por el usuario, el sistema o dispositivos externos.

🖱️ clic ⌨️ teclado 🖱️ mouse ⏱️ temporizadores 📡 sensores 📨 mensajes de red 📊 llegada de datos

"Don't call us, we'll call you."

Componentes Clave de POE

20 min

📊 Flujo de la Programación Orientada a Eventos

Evento → Bucle de Eventos → Cola de Mensajes → Oyente/Controlador
🔔

Eventos

Acciones o sucesos que desencadenan una respuesta del sistema. Ejemplos: clic, tecla presionada, mensaje recibido, temporizador.

🔄

Bucle de Eventos

Ciclo sostenido que espera a que ocurran eventos y los procesa cuando suceden. Es el motor invisible de la POE.

👂

Oyentes / Controladores

Funciones o métodos que se ejecutan cuando se detecta un evento específico. También conocidos como listeners o handlers.

📨

Colas de Mensajes

En sistemas más sofisticados, los mensajes suelen colocarse en colas para ser ejecutados en un orden controlado, evitando pérdidas y garantizando procesamiento.

📝 ¿Cómo funciona este flujo?

1. Evento: El usuario hace clic en un botón.
2. Bucle de Eventos: Detecta el clic y lo pone en la cola.
3. Cola de Mensajes: Organiza los eventos pendientes.
4. Controlador: Ejecuta la función asociada al evento.
⚖️

Ventajas y Desafíos de POE

✅ Ventajas

  • Capacidad de respuesta: Reacciona de inmediato a entradas del usuario o eventos del sistema.
  • Modularidad: Controladores separados facilitan mantenimiento y depuración.
  • Escalabilidad: Añadir nuevos controladores sin reestructurar el código base.
  • Tiempo real: Ideal para sistemas que requieren respuestas inmediatas.
  • Asincronía: Mejora el rendimiento y la utilización de recursos.

⚠️ Desafíos

  • Depuración compleja: El flujo de ejecución es difícil de rastrear en aplicaciones grandes.
  • Imprevisibilidad: Dificultad para predecir cuándo ocurrirán los eventos.
  • Callback Hell: Múltiples callbacks anidados pueden crear código espagueti.
  • Consumo de recursos: Puede ser ineficiente en ciertos escenarios.

🔥 Problema: Callback Hell

Cuando se anidan muchas funciones de devolución de llamada, el código se vuelve difícil de leer y mantener:

doA(() => {
    doB(() => {
        doC(() => {
            doD(() => {
                // Código difícil de seguir
            });
        });
    });
});

💡 Solución: Usar Promesas, Async/Await o patrones como Pub/Sub para evitar el anidamiento.

Comparación: Secuencial vs Eventos

Característica Programación Secuencial Programación Orientada a Eventos
Orden Orden fijo, predecible Depende de eventos
Control El programador controla el flujo El usuario controla el flujo
Flujo Flujo lineal Flujo dinámico
Ciclo de vida Inicio → Fin Espera continuamente
Comunicación Llamada directa Suscripción (Pub/Sub)

Ejemplos paso a paso

20 min
NIVEL 1

📌 Ejemplo 1: Programa Secuencial (Sin eventos)

Todo ocurre en orden estricto. El programa controla el flujo:

// Programa secuencial - todo ocurre en orden
console.log("Programa iniciado");

function saludar() {
    console.log("¡Hola estudiante!");
}

saludar();  // Llamada directa a la función

console.log("Programa finalizado");

// Salida esperada:
// Programa iniciado
// ¡Hola estudiante!
// Programa finalizado

💡 Observación: El programa controla cuándo se ejecuta saludar(). No hay espera ni eventos.

NIVEL 2

⏱️ Ejemplo 2: Primer Evento (setTimeout)

El programa no se bloquea. La función se ejecuta después de un tiempo:

console.log("1. Programa iniciado");

// Evento basado en tiempo
setTimeout(() => {
    console.log("3. ¡Hola después de 2 segundos!");
}, 2000);

console.log("2. Esto se ejecuta mientras espera");

// Salida esperada:
// 1. Programa iniciado
// 2. Esto se ejecuta mientras espera
// 3. ¡Hola después de 2 segundos!

💡 Concepto clave: El programa no espera. El "2" se muestra antes del "3". ¡Eso es asincronía!

NIVEL 3

📌 Ejemplo 3: Evento con función externa

El evento ejecuta una función definida por separado. El sistema llama a la función:

// Función que se ejecutará cuando ocurra el evento
function mostrarMensaje() {
    console.log("📨 ¡Evento activado!");
}

console.log("Esperando evento...");

// El temporizador ejecutará mostrarMensaje después de 3 segundos
setTimeout(mostrarMensaje, 3000);

// Salida esperada:
// Esperando evento...
// 📨 ¡Evento activado! (después de 3 segundos)

💡 Concepto clave: El sistema llama a la función. Tú no la llamas directamente. Esto es el Hollywood Principle.

NIVEL 4

🖱️ Ejemplo 4: Evento en el navegador (clic)

El usuario controla el flujo. El programa espera a que el usuario haga clic:

// 1. Seleccionar el botón
const boton = document.getElementById("miBoton");

// 2. Función que se ejecutará al hacer clic
function manejarClic() {
    alert("¡Hiciste clic en el botón!");
}

// 3. Registrar el evento
boton.addEventListener("click", manejarClic);

console.log("El programa está escuchando...");

// El programa NO se bloquea. Solo reacciona cuando el usuario hace clic.

💡 Concepto clave: El usuario decide cuándo ocurre el evento. El programa espera y reacciona.
