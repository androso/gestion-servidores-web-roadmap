Introducción a las Interfaces Gráficas

📌 ¿Qué es una Interfaz Gráfica (GUI)?

Una Interfaz Gráfica de Usuario (GUI, por sus siglas en inglés) es un sistema de elementos visuales que permite a los usuarios interactuar con un software mediante imágenes, iconos y componentes visuales, en lugar de hacerlo solo con texto o comandos.

🔹 Características principales

  • Intuitiva: Fácil de entender para el usuario.
  • Interactiva: Responde a las acciones del usuario.
  • Visual: Usa elementos gráficos en lugar de texto.
  • Basada en eventos: Reacciona a clics, teclas, etc.

🔹 Ejemplos cotidianos

  • Sistemas operativos: Windows, macOS, Linux.
  • Aplicaciones móviles: WhatsApp, Instagram, etc.
  • Páginas web: Interfaz web con HTML/CSS/JS.
  • Software de escritorio: Word, Photoshop, etc.

💡 En POE: Las interfaces gráficas son el ejemplo más claro de Programación Orientada a Eventos. Cada clic, tecla o movimiento del mouse dispara un evento que el programa debe manejar.

Etiquetas (Labels)

📌 ¿Qué es una etiqueta?

Una etiqueta (o label) es un componente gráfico que muestra texto estático en la interfaz. Su propósito es informar al usuario sobre qué representa otro elemento o proporcionar instrucciones.

🔹 Características

  • Texto estático (no editable por el usuario).
  • Puede ser modificado por el programa.
  • No genera eventos (no interactivo).
  • Se usa para identificar otros componentes.

🔹 Tipos de etiquetas

  • Texto simple: "Nombre:", "Contraseña:"
  • Títulos: "Gestión de Usuarios"
  • Subtítulos: "Complete el formulario"
  • Mensajes de estado: "Conexión exitosa"

🔹 Buenas prácticas

  • Texto claro y conciso.
  • Alineación consistente.
  • Usar fuentes legibles.
  • Colores contrastantes.

📌 Ejemplo en HTML (componente visual)

// Etiqueta simple
<label for="nombre">Nombre completo:</label>

// Etiqueta estilizada
<label style="font-weight: bold; color: #0e3f68;">Bienvenido, Usuario</label>

💡 Para POE: Las etiquetas pueden cambiar su contenido en respuesta a eventos. Por ejemplo, mostrar "Cargando..." mientras se procesa una acción.

Botones (Buttons)

📌 ¿Qué es un botón?

Un botón es el componente más importante de cualquier GUI. Es un elemento interactivo que el usuario puede presionar para desencadenar una acción. Es el corazón de la interacción usuario-sistema.

🔹 Características

  • Interactivo: Responde al clic del usuario.
  • Texto: Describe la acción que realizará.
  • Evento: Dispara un evento al ser presionado.
  • Estados: Normal, hover, presionado, deshabilitado.

🔹 Tipos de botones

  • Botón de acción: "Guardar", "Enviar", "Aceptar"
  • Botón de cancelación: "Cancelar", "Cerrar"
  • Botón de navegación: "Siguiente", "Atrás"
  • Botón con icono: Solo imagen o icono + texto

📌 Ejemplo en HTML + Evento

// Botón en HTML
<button id="btnEnviar" class="boton-primario">Enviar formulario</button>

// Evento en JavaScript
const boton = document.getElementById('btnEnviar');
boton.addEventListener('click', () => {
    // Acción que se ejecuta al hacer clic
    console.log('¡Botón presionado!');
});

💡 Para POE: Los botones son el origen de eventos más común. Cada clic es un evento que el sistema debe manejar, ejecutando la acción correspondiente.

📌 Buenas prácticas en botones:

  • Texto claro y orientado a la acción ("Guardar" vs "Aceptar").
  • Ubicación consistente en la interfaz.
  • Diferenciar acciones primarias (color principal) y secundarias.
  • Proporcionar retroalimentación visual al hacer clic (cambio de color, loading, etc.).

Campos de Texto (Inputs)

📌 ¿Qué es un campo de texto?

Un campo de texto (o input) es un componente que permite al usuario ingresar datos en forma de texto. Es la forma principal de entrada de datos en cualquier interfaz.

🔹 Tipos de campos

  • Texto simple: Nombre, dirección, etc.
  • Contraseña: Oculta el texto ingresado.
  • Correo electrónico: Valida formato de email.
  • Número: Solo permite dígitos.
  • Textarea: Múltiples líneas de texto.

🔹 Eventos asociados

  • change: Cuando se modifica el valor.
  • input: Cada vez que se escribe.
  • focus: Cuando el campo recibe el foco.
  • blur: Cuando el campo pierde el foco.

🔹 Buenas prácticas

  • Usar etiquetas claras y visibles.
  • Proporcionar placeholders (texto de ayuda).
  • Validar los datos ingresados.
  • Feedback visual de errores.

📌 Ejemplo en HTML

// Campo de texto simple
<label for="nombre">Nombre completo:</label>
<input type="text" id="nombre" placeholder="Ingrese su nombre" />

// Campo de contraseña
<label for="password">Contraseña:</label>
<input type="password" id="password" />

// Textarea (múltiples líneas)
<textarea id="mensaje" rows="4" placeholder="Escriba su mensaje..."></textarea>

💡 Para POE: Los campos de texto son fuentes de eventos continuos. Cada carácter que el usuario escribe puede disparar eventos de validación, autocompletado o actualización en tiempo real.

Listas (Listas, Dropdowns y Selectores)

📌 ¿Qué es una lista en GUI?

Una lista es un componente que permite al usuario seleccionar una o más opciones de un conjunto predefinido. Ayuda a evitar errores al limitar las opciones disponibles.

🔹 Tipos de listas

  • Lista desplegable (dropdown): Selección de una opción.
  • Lista de selección múltiple: Varias opciones a la vez.
  • Lista simple: Muestra opciones visibles.
  • Radio buttons: Selección única con visualización directa.
  • Checkboxes: Selección múltiple con visualización directa.

🔹 Eventos asociados

  • change: Cuando se selecciona una opción.
  • click: En elementos de la lista.
  • dblclick: Doble clic en un elemento.

🔹 Buenas prácticas

  • Ordenar opciones lógicamente.
  • Usar opción placeholder ("Seleccione...").
  • Agrupar opciones si son muchas.
  • Deshabilitar opciones no disponibles.

📌 Ejemplo en HTML

// Dropdown (selección única)
<label for="ciudad">Ciudad:</label>
<select id="ciudad">
  <option value="">Seleccione...</option>
  <option value="SJO">San Salvador</option>
  <option value="STA">Santa Ana</option>
</select>

// Lista con selección múltiple
<select multiple size="3">
  <option>Opción 1</option>
  <option>Opción 2</option>
  <option>Opción 3</option>
</select>

💡 Para POE: Las listas generan eventos cuando el usuario cambia la selección. Esto permite actualizar otros componentes de la interfaz en tiempo real.

Eventos en Interfaces Gráficas

📌 ¿Qué son los eventos GUI?

Los eventos son acciones que ocurren en la interfaz y que el sistema puede detectar y manejar. Son el puente entre el usuario y el programa.

🖱️ Eventos de mouse

  • click: Un clic en el elemento.
  • dblclick: Doble clic.
  • mouseenter: El mouse entra al elemento.
  • mouseleave: El mouse sale del elemento.
  • mousemove: El mouse se mueve sobre el elemento.

⌨️ Eventos de teclado

  • keydown: Se presiona una tecla.
  • keyup: Se suelta una tecla.
  • keypress: Tecla presionada y soltada.

📝 Eventos de formulario

  • focus: El elemento recibe el foco.
  • blur: El elemento pierde el foco.
  • change: El valor cambia.
  • input: Se escribe en el campo.
  • submit: Se envía un formulario.

📌 Diagrama del flujo de eventos GUI

Usuario realiza una acción (clic, tecla, etc.)
        ↓
Sistema detecta el evento
        ↓
Evento se coloca en la cola de eventos
        ↓
Bucle de eventos lo procesa
        ↓
Se ejecuta el manejador (handler)
        ↓
La interfaz se actualiza

💡 Para POE: Las interfaces gráficas son sistemas puramente basados en eventos. Cada interacción del usuario es un evento que el programa debe manejar.

Principios de Diseño de Interfaces

📌 Principio de Consistencia

Los elementos similares deben verse y comportarse de la misma manera en toda la interfaz. Esto reduce la curva de aprendizaje del usuario.

📌 Principio de Retroalimentación

El usuario debe saber qué está pasando. Cada acción debe tener una respuesta visual (cambio de color, mensaje, animación, etc.).

📌 Principio de Jerarquía

Los elementos más importantes deben ser más visibles. Usar tamaño, color y posición para guiar la atención del usuario.

📌 Principio de Prevención de Errores

Diseñar para evitar que el usuario cometa errores. Usar validaciones, confirmaciones y opciones limitadas.

📌 Consejos prácticos para GUI

  • Menos es más: No saturar la interfaz con elementos innecesarios.
  • Alineación: Mantener elementos alineados para una apariencia limpia.
  • Espaciado: Usar espacios adecuados entre elementos.
  • Contraste: Asegurar buena legibilidad del texto.
  • Accesibilidad: Diseñar para todos los usuarios, incluyendo personas con discapacidades.

Resumen de Conceptos Clave

🖥️ Interfaz Gráfica (GUI)

Sistema visual que permite interactuar con el software mediante elementos gráficos.

🏷️ Etiquetas (Labels)

Texto estático para identificar o describir otros componentes.

🔘 Botones (Buttons)

Elemento interactivo que desencadena acciones al ser presionado.

✏️ Campos de Texto

Permiten al usuario ingresar datos de texto en la interfaz.

📋 Listas

Permiten seleccionar una o más opciones de un conjunto predefinido.

⚡ Eventos GUI

Acciones del usuario que el sistema detecta y maneja (clic, tecla, cambio, etc.).

💡 Conclusión: Los componentes GUI básicos (etiquetas, botones, campos de texto y listas) son la base de cualquier interfaz de usuario. Su correcta implementación y diseño determinan la experiencia del usuario y la eficacia del sistema. En POE, estos componentes son emisores de eventos que desencadenan la lógica de la aplicación.
