📖 Contenido de la Clase

1. El Gran Cambio de Mentalidad: Los Paradigmas de Programación

Para entender la Programación Orientada a Eventos, primero debemos entender contra qué compite. Un paradigma de programación es la filosofía o el enfoque que usamos para resolver un problema con código.

📌 Programación Secuencial / Estructurada

El código se ejecuta de arriba a abajo. El programa tiene el control absoluto del flujo. Si necesita un dato, se detiene, te lo pide (input()) y hasta que no respondes, el programa no avanza. Es como leer un libro: vas página por página.

// Ejemplo en JavaScript
console.log("Paso 1: Iniciar programa");
const nombre = prompt("¿Cuál es tu nombre?"); // Se detiene aquí
console.log("Paso 2: Hola " + nombre);
console.log("Paso 3: Fin del programa");

📌 Programación Orientada a Eventos (POE)

El flujo del programa no lo decide el programador en una secuencia fija; lo decide el usuario, el sistema o factores externos. El programa se queda "escuchando" en un bucle infinito y reacciona solo cuando algo pasa. Es como estar en una fiesta: estás tranquilo hasta que suena el timbre, alguien te habla o se acaba la música. Tú no controlas cuándo pasa, solo reaccionas.

// Ejemplo en JavaScript (navegador)
document.getElementById("miBoton").addEventListener("click", () => {
    alert("¡El usuario hizo clic!"); // Solo se ejecuta cuando ocurre el evento
});

console.log("El programa sigue escuchando...");

💡 Reflexión:

En la programación secuencial, el programa pregunta. En la POE, el programa escucha.

2. Conceptos Básicos de POE: Los 4 Pilares

Para que un sistema orientado a eventos funcione, interactúan cuatro elementos clave:

[Origen del Evento] → (El Evento) → [Bucle de Eventos] → [Manejador/Handler]

🔹 El Evento (Event)

Cualquier acción o suceso detectable. Ejemplos: clic, cambio de temperatura, mensaje recibido, error del sistema.

🔹 Origen / Emisor (Event Source)

Objeto que genera el evento. Ejemplos: botón, teclado, temporizador, tarjeta de red.

🔹 Bucle de Eventos (Event Loop)

Motor invisible que pregunta constantemente: "¿Pasó algo?". Detecta y despacha eventos sin congelar el sistema.

🔹 Manejador (Event Handler)

Función que se ejecuta específicamente para responder a un evento. when(button.click) execute(showAlert)

💡 Analogía del Restaurante:

El cliente (Origen) pide un plato (Evento). El mesero (Bucle de Eventos) recoge el pedido y lo lleva a la cocina (Manejador) que prepara la comida. El cliente no controla cuándo llegará la comida, solo espera y reacciona cuando llega.

3. La Comparativa: POO Tradicional vs. POE

Es muy común confundirlas porque la mayoría de las interfaces gráficas modernas usan ambas al mismo tiempo (programamos interfaces orientadas a eventos usando objetos). Sin embargo, conceptualmente son muy distintas:

Característica POO Tradicional Programación Orientada a Eventos
Enfoque Central Datos y Estructura: Modelar el mundo real en clases, atributos y métodos. Acciones y Respuestas: Reaccionar al entorno dinámicamente.
Control del Flujo El Servidor/Algoritmo: Un método llama a otro de forma predecible y síncrona. El Usuario/Entorno: El flujo es impredecible; depende de qué botón se toque primero.
Estilo de Comunicación Llamada Directa: El Objeto A llama explícitamente al método del Objeto B. Suscripción (Publish/Subscribe): El emisor lanza el evento al aire; no le importa quién lo escuche.
Acoplamiento Fuerte: El código que inicia la acción debe conocer al objeto que la ejecuta. Débil: El botón no sabe qué va a pasar cuando lo presionen, solo avisa que lo presionaron.

💡 La analogía definitiva:

POO Tradicional es como un cajero automático: Te pide la tarjeta → te pide el PIN → te pregunta cuánto dinero quieres → te da el dinero. No puedes saltarte pasos.

POE es como una página web moderna: Puedes hacer scroll, dar me gusta, abrir un chat, cambiar a modo oscuro o cerrar la pestaña. Todo está disponible a la vez y la web responde a lo que tú decidas hacer en el orden que quieras.

4. ¿Dónde se usa la POE?

Esta arquitectura no sirve para algoritmos matemáticos puros, pero es indispensable en:

🖥️ Interfaces Gráficas (GUI)

Aplicaciones móviles, webs y de escritorio. Cada clic, scroll o tecla es un evento.

🌐 Desarrollo Web

JavaScript y Node.js corren sobre un Event Loop. Cada petición HTTP es un evento.

🎮 Videojuegos

El motor escucha inputs del control (moverse, disparar) mientras actualiza la pantalla.

📡 Internet de las Cosas (IoT)

Sensores que "despiertan" al procesador solo cuando detectan movimiento, humo o caídas de tensión.

🎯 Resumen de la Clase

  • Paradigmas: La POE es un cambio de mentalidad donde el programa escucha en lugar de preguntar.
  • 4 Pilares: Evento, Origen, Bucle de Eventos y Manejador trabajan juntos para crear sistemas reactivos.
  • POO vs POE: La POE prioriza acciones y respuestas sobre datos y estructura.
  • Aplicaciones: Interfaces gráficas, web, videojuegos, IoT y cualquier sistema que reaccione a estímulos externos.
